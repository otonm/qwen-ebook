## Phase Goal

**As a** person who owns long text (ebooks, articles), **I want to** upload a `.txt` file and receive back a single audible narrated audio file produced end-to-end by self-hosted Qwen TTS, **so that** I can listen to my own text as audio on my commute or workout.

> Phase 1 substitutes the usual Walking-Skeleton "one real UI interaction" with one real HTTP-client (`curl`/Postman) interaction, since all frontend work is deferred to Phase 2/3 (D-05/D-06). This plan (01) delivers that path end-to-end with a mock TTS backend; Plan 02 retires the GPU risk; Plan 03 wires the real GPU container in.

<objective>
Build the Walking Skeleton: a real FastAPI backend that accepts a `.txt` upload, chunks it on paragraph boundaries, synthesizes each chunk (via a mock TTS backend this plan, real GPU backend later), joins the per-chunk WAVs with ffmpeg, and returns one downloadable audio file — the full end-to-end path proven with `TTS_BACKEND=mock` and zero GPU dependency.

Purpose: Establishes the real app skeleton (D-05) and retires all non-GPU risk, so the GPU spike (Plan 02) and two-container integration (Plan 03) plug into a proven pipeline. Also defines the internal `/synthesize` HTTP contract that Plan 02 implements.
Output: `backend/` scaffold + working `POST /projects` endpoint + passing unit and e2e tests, all runnable on a GPU-less machine.
</objective>

| Boundary | Description |
|----------|-------------|
| HTTP client (curl/Postman) → FastAPI `/projects` | Untrusted uploaded file bytes and client-supplied filename cross here |
| Backend app → `ffmpeg` subprocess | App-generated filenames passed to an external process |
| Backend app → TTS service (`http` backend) | Internal pod-network call; server implemented in Plan 02 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `main.py` upload path construction | mitigate | Generate server-side `uuid4()` filenames; never use `UploadFile.filename` in a filesystem path; write only under `UPLOAD_DIR`/`OUTPUT_DIR` (Task 3) |
| T-01-02 | Denial of Service | `main.py` upload size | mitigate | Enforce `MAX_UPLOAD_BYTES` (default 10 MiB); reject oversized with `413` before unbounded buffering (Task 3) |
| T-01-03 | Tampering | `audio_join.py` ffmpeg call | mitigate | `subprocess.run([...])` arg-list only; never `shell=True`/string interpolation (Task 2, regression-checked Task 3) |
| T-01-04 | Information Disclosure | `main.py` decode of non-text upload | mitigate | Guard UTF-8 decode, return `400` on `UnicodeDecodeError` (no 500 stack leak) (Task 3) |
| T-01-SC | Tampering | `uv`/pip installs (backend deps) | accept | All backend packages `[VERIFIED]`/`OK` in RESEARCH.md Package Legitimacy Audit (slopcheck clean); versions pinned in `pyproject.toml`. No `[ASSUMED]`/`[SUS]` packages → no blocking legitimacy checkpoint required |
