<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host client (curl) → backend container `:8000` | Untrusted upload enters the pod (validated in Plan 01) |
| Backend container → TTS container `:8001` (pod-internal) | Chunk text crosses the internal boundary; TTS port not host-exposed |
| Host → GPU devices on the TTS container only | Device access scoped to one container, not the backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure / Spoofing | TTS container network exposure | mitigate | Publish ONLY backend port `8000` to the host; keep TTS `8001` internal to the pod (not host-published), so the GPU service is unreachable except via the backend (Task 1) |
| T-03-02 | Denial of Service | Backend hangs on TTS failure/timeout | mitigate | `tts_client` uses bounded httpx timeouts (Plan 01); backend maps TTS connection failure/timeout to `502`/`504`, verified by the negative integration test (Task 2) |
| T-03-03 | Tampering | ffmpeg subprocess in the deployed backend | mitigate | Inherits Plan 01 arg-list `subprocess.run` (no `shell=True`); no regression introduced by containerization |
| T-03-04 | Elevation of Privilege | GPU devices leaking to the CPU backend | mitigate | Pod definition passes `/dev/kfd`+`/dev/dri` to the `tts` container ONLY; verified via `podman inspect` at the Task 3 checkpoint |
| T-03-SC | Tampering | container base images / apt/pip installs | accept | `python:3.12-slim` + official `rocm/pytorch` base tag (verified); backend deps `[VERIFIED]`/`OK` in RESEARCH.md audit, pinned. No `[ASSUMED]`/`[SUS]` packages -> no blocking legitimacy checkpoint |
</threat_model>
