Root cause (03-UAT.md test 4): generate_project unconditionally spawns a new
run_batch_generation on every call, and the worker's startup stale-reset
unconditionally flips any 'generating' row back to 'pending' assuming a crash
leftover — it cannot tell that from work genuinely in flight. A second click
races the first.

Add a per-project in-flight registry so a live run is distinguishable. In
generation_worker.py add module-level `_running_generations: dict[str, asyncio.Task]`
plus small helpers: is_generation_running(project_id) -> bool (task present and
not done) and get_generation_task(project_id). Keep it next to the existing
_generation_progress_queues registry discipline.

generate_project (main.py, ~line 762): before spawning, check
is_generation_running(project_id). If a live task exists, return WITHOUT
spawning a second — respond e.g. {"status": "already_running"} (keep 202, or use
409; pick one and note it — the frontend just needs to know it was not started).
If none is running, create the task, register it in _running_generations under
project_id, and add a done-callback that removes it from _running_generations
(in addition to the existing _background_tasks bookkeeping). The stale-reset in
run_batch_generation is now CORRECT again: a new batch only starts when no live
task exists, so any 'generating' row it sees really is a crash leftover.

Per-row generate_segment (main.py, ~line 688): before starting, reject a
duplicate. If the segment's current generation_status is already 'generating',
return 409 (detail like "Segment is already generating") instead of setting
'generating' again and awaiting a second concurrent regenerate_segment for the
same row. (This covers a row already generating via a batch run or an earlier
per-row click.)

Tests (test_generation.py): use a controlled/slow mock synth (the
monkeypatch pattern already in test_patch_bumps_generation_version) to hold a
batch in flight, then:

    only ONE run_batch_generation task ran (e.g. assert synth call count matches
    a single pass).
  - assert POST /segments/{id}/generate on a row whose status is 'generating'
    returns 409.
Keep the existing batch tests green.
