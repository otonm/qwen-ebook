<objective>
Close the frontend half of the test-4 gaps: (1) the per-row Generate/Play button
tracks only its own local click state, so a row already 'generating' (via a
batch or another trigger) still shows an enabled button and fires a duplicate
generate; (2) Generate All stays clickable while a per-row generate is in flight
because isRunning only reflects the batch SSE stream; (3) there is no way to stop
a running generation; (4) the Config Panel's preview Play button is inertly
disabled with no explanation and no way to produce a preview.

Purpose: make the generation controls honest and controllable (TBL-04, CFG-02/03,
GEN-05), on top of the backend guards + cancel/preview endpoints from plan 08.
Output: status-driven per-row controls, a batch Stop control, and an on-demand
preview trigger.
</objective>

  - triggerCharacterPreview(characterId): POST /characters/{characterId}/preview

SegmentTable.tsx GeneratePlayButton (03-UAT.md test 4 continuation): today
`disabled={isGenerating}` reflects only this button instance's own local
click-in-flight state and never reads segment.generation_status, so a row that's
'generating' for any other reason (a batch run) keeps an enabled button and a
click fires a second POST /segments/{id}/generate.

Derive the live generating state from the segment: the row is generating when
`segment.generation_status === "generating"` OR the local isGenerating click
flag is set. Use that combined value to:
  - disable the button, and
  - show the spinner (Loader2) — so a batch-driven 'generating' row shows a
    spinner and is un-clickable just like a locally-triggered one.
Keep the existing has-audio play/pause behavior. ProjectScreen already feeds
liveSegments (SSE status merged) into SegmentTable, so segment.generation_status
is live — no new plumbing needed here.

<task type="auto">
  <name>Task 2: Config Panel — Generate All guard, Stop control, on-demand preview</name>

  <action>
ConfigPanel.tsx (03-UAT.md test 4):

(a) Generate All disabled state — currently isRunning = generation.status ===
"running" || isStarting, which misses a per-row generate in flight. Also disable
when ANY segment is generating: compute anyGenerating =
segments.some(s => s.generation_status === "generating") and disable the button
when isRunning || anyGenerating. (segments here is liveSegments — live status.)

(b) Stop control — while a batch is running (generation.status === "running" ||
isStarting), render a Stop button next to/under Generate All that calls
cancelBatchGeneration(project.id). After it resolves, the batch SSE stream
settles via plan 08's terminal cancel event and ProjectScreen refetches. Keep
copy honest per the threadpool ceiling documented in plan 08: label/help text
should say it stops the run (the segment currently synthesizing may finish) —
do not imply instant mid-segment abort.

(c) Preview control (CharacterPreviewRow) — today the Play button is silently
`disabled={!hasPreview}` with no explanation, and a character whose voice was
never re-saved has a permanently null preview. When there is no preview:
  - give the disabled Play button an explanatory tooltip/aria (e.g. title="No
    preview generated yet"), and
  - render a small "Generate preview" button that calls
    triggerCharacterPreview(character.id), then triggers a project refresh so the
    new preview_audio_path lands and Play enables. Show a brief generating state
    while it is in flight.

ProjectScreen.tsx — pass a refresh callback down so the Config Panel can pick up
a freshly generated preview: expose the existing `refetch` (or a thin wrapper)
as an `onRefresh` prop to ConfigPanel. ConfigPanel calls it after
triggerCharacterPreview resolves (preview generation is a background task, so a
single refetch shortly after may still show null — a short poll of getProject a
couple times, or re-calling onRefresh on an interval until preview_audio_path is
set, is acceptable; keep it minimal). Do not add a state library — local
state/effect only.

Run `cd frontend && npm run build`.
