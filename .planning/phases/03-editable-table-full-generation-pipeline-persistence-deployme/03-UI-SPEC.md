## Layout

Two-region page (not in the base template but load-bearing for this phase — CFG-01 explicitly specifies the split):

- **Segment table region: ~70% width** — the editable table (TBL-01..04).
- **Config panel region: ~30% width** — input file / model / output format / output file (CFG-01), character list + preview controls (CFG-02), live progress (CFG-03). Sits to the right, matches the width ratio stated in REQUIREMENTS.md/ROADMAP.md verbatim.
- Both regions are always visible together on one screen (no tab-switching between "table" and "config") — consistent with Phase 2's D-14/D-15 single-page philosophy this phase's UI-SPEC extends.

**Screens (navigation placement — Claude's discretion per CONTEXT.md, resolved here):**
1. **Project List** (`/`) — PERS-02's new list screen. Root/landing route. Shows saved projects (filename, date, status badge) as a list of `card` rows, each with an "Open" action. A persistent **"New Project"** button (top of the list) starts the existing Phase 2 upload flow.
2. **Upload/Analyzing** — Phase 2's existing flow, unchanged, reached via "New Project."
3. **Table + Config** (`/projects/:id`) — this phase's main new screen, reached by opening a project from the list or automatically after analysis completes. A small persistent header link ("← Projects") returns to the list without losing project state (autosave-by-construction per PERS-01 means there's nothing to lose).

## Spacing Scale

Declared values (must be multiples of 4) — same scale as Phase 2:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding |
| sm | 8px | Compact spacing (checkbox-to-cell-content, status badge internal padding) |
| md | 16px | Default spacing between config panel sections, table cell horizontal padding |
| lg | 24px | Spacing between project-list rows, config panel section padding |
| xl | 32px | Gap between the 70% table region and the 30% config panel |
| 2xl | 48px | Page-header-to-content spacing (project list heading to first row) |
| 3xl | 64px | Not used this phase |

**Exceptions:**
- Segment table's per-row generate/play-pause icon button uses shadcn `size="sm"` icon variant (**32px** square) instead of the wizard's `size="icon"` (36px) default — a book-length table needs a tighter row height than the character-card wizard did. 32px is still a multiple of 4; this is a desktop-only Tailscale tool (no mobile touch-target minimum applies, per PROJECT.md Out of Scope).
- Bulk-action toolbar (appears above the table when 1+ rows selected) uses a fixed **48px** height bar — a multiple of 4, sized to comfortably hold the row-count label + reassign dropdown + confirm button in one line without wrapping.

## Typography

Same 4 sizes / 2 weights as Phase 2 — no new sizes introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

- **Body (14/400/1.5):** Text cell content, Voice Instructions cell content, project-list filename, config panel field values.
- **Label (12/600/1.4):** Column headers (Narrator/Voice Instructions/Text), generation-status badges ("pending"/"generating"/"complete"/"error"), project-list status badge, bulk toolbar's "N selected" label, config panel field labels ("Input File", "Model", "Output Format", "Output File").
- **Heading (18/600/1.2):** "Segments" table section header (carried from Phase 2's `SegmentPreview.tsx`), "Characters" config-panel sub-header, project-list page heading.
- **Display (24/600/1.2):** Not newly used this phase beyond the project filename heading on the Table+Config screen (same role as Phase 2's page title).

## Color

Same palette as Phase 2 — no new hues:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` (zinc `background`, white) | Page background, table surface |
| Secondary (30%) | `oklch(0.967 0.001 286.375)` (zinc `secondary`/`muted`) | Config panel background, project-list row cards, alternating table row stripe (unchanged from `SegmentPreview.tsx`) |
| Accent (10%) | `oklch(51.1% 0.262 276.966)` (indigo-600, `--primary`) | See reserved list below — the only place accent appears |
| Destructive | `oklch(0.577 0.245 27.325)` (shadcn default destructive red, unchanged) | Segment "error" status only — no other new destructive use this phase |

**Accent reserved for** (explicit list — extends Phase 2's list with this phase's new elements; nothing else uses indigo):
- "Generate All" primary CTA button (config panel, batch generation trigger)
- "New Project" CTA (project list screen)
- Play/pause preview button while actively playing (Phase 2's rule, still applies — character preview in config panel AND per-row segment playback in the table)
- Selected/focused character card ring (Phase 2's rule, unchanged — config panel character list)
- "Voice assigned" checkmark badge on a character card (Phase 2's rule, unchanged)
- Per-segment "generating" status badge/spinner — the one moment a row is actively synthesizing (batch or per-row regen)
- Batch generation overall progress bar fill (`Progress` component's default fill, already indigo via `--primary`)
- Row-selection checkboxes' checked state + header "select all" checkbox's checked state (shadcn `Checkbox`'s default checked = `--primary`)
- Bulk toolbar's confirm action button (e.g. "Reassign 4 segments")

Everything else — table borders, card backgrounds, "Cancel"/secondary buttons, the "pending"/"queued"/"complete" status badges — stays zinc-neutral. **Do not invent a semantic "success green" for the "complete" status** — use a neutral badge with a checkmark icon (`CheckCircle2` from lucide, `text-foreground` or `text-muted-foreground`), not a new color. Only "error" gets the destructive red; every other status stays zinc.

### Generation Status Indicators (new vocabulary this phase — GEN-05, TBL-04, CFG-03)

Prescriptive mapping so the executor doesn't invent a new palette per status:

| Status | Badge style | Icon (lucide) |
|--------|------------|----------------|
| `pending` | Neutral outline badge, `text-muted-foreground` | `Clock` |
| `queued` | Neutral outline badge, `text-muted-foreground` | `Clock` (same as pending — queued is a batch-only sub-state, no visual distinction needed) |
| `generating` | Accent-tinted badge (`--primary`), text label "Generating…" | `Loader2` with `animate-spin` |
| `complete` | Neutral solid badge, `text-foreground` | `CheckCircle2` |
| `error` | Destructive badge (`--destructive`) | `AlertCircle` |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Generate All"** — starts/resumes batch generation for the whole project (GEN-05, CFG-03); relabels to **"Resume Generation"** when reopening a project with a mix of complete/pending/error rows so the user understands it's not starting over |
| Secondary CTA (project list) | **"New Project"** — starts the existing Phase 2 upload flow |
| Empty state heading (project list) | **"No projects yet"** |
| Empty state body (project list) | **"Upload a book to create your first project."** + the New Project CTA |
| Error state — per-segment generation failure | Row's status badge reads **"Error"**; on hover/click, show `{reason}` (e.g. "TTS service didn't respond — try again.") inline. The per-row generate button re-triggers that single segment (no separate "retry" affordance needed — same button, same action) |
| Error state — batch join blocked | **"Can't create the final file yet."** + **"{N} segment(s) failed to generate. Fix or regenerate them, then try again."** (per Open Question 1's resolution: block the join rather than silently skipping failed segments — no "last good" fallback in v1 per ENH-02 deferral) |
| Error state — project list load failure | **"Couldn't load your projects."** + **"Check the connection and try again."** |
| Destructive confirmation | **None new this phase.** Bulk-reassign (TBL-03) and auto-regenerate-on-blur (GEN-03/D-06) are both non-destructive and freely re-editable — no confirmation step, matching D-06's explicit "no separate Save or confirm-regenerate step." Phase 2's existing merge-character confirmation dialog is unchanged and out of this phase's scope. |
