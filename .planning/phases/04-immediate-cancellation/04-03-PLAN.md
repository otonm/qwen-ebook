<objective>
Do the structural backend work GEN-06/07/08 require: make per-segment generation an addressable background task, give segment and character-preview generation cancellable task handles via a label-keyed registry, and add the three cancel behaviors — a new per-segment cancel endpoint, a new character-preview cancel endpoint, and an extension of the existing batch cancel — each calling `tts_client.cancel()` (the true GPU-call kill from 04-02) in addition to cancelling the local asyncio task. Hold the single-flight lock until the underlying synth call is confirmed stopped so a stop→immediately-generate-again cycle can never race two `/synthesize` calls. This is the core of the phase.

Purpose: Today only the batch path has a cancellable handle, and segment generate is awaited synchronously inline (Pitfall 3). "Add a Stop button" is really "restructure the call as an addressable, cancellable task and hold the lock honestly."
Output: label-keyed `_running_generations` + lookup helpers; async 202 `generate_segment`; `POST /segments/{id}/generate/cancel`; `POST /characters/{id}/preview/cancel`; batch cancel extended with `tts_client.cancel()`; reset-to-pending on cancel; the ponytail ceiling comment on `cancel_generation` removed/rewritten; regression tests.
</objective>
