## Phase Goal

**As a** reader who owns a long text, **I want to** upload it and have the app auto-detect its cast (consistently, even across a long multi-chunk book) and split it into voice-tagged segments, **so that** I get a multi-character narration set up with minimal manual editing.

This slice replaces Plan 01's mock analysis stub with the real Grok call and adds the cross-chunk cast-continuity path — so real books, including oversized ones, produce a real, de-duplicated cast.

<objective>
Implement the real `xai-sdk` analysis backend (CAST-01/CAST-03) and the oversized-text multi-chunk fallback with running-cast + last-20-segment continuity context and LLM-side reconciliation (CAST-02, D-05..D-08).

Purpose: This is the app's differentiator and the phase's MEDIUM-confidence risk (per STATE.md) — the reconciliation strategy is a synthesized best-practice, so it is built behind the mock-testable worker seam and validated with a deterministic multi-chunk test plus an optional real-key smoke check.
Output: real `analyze()` implementation + system prompt, the worker's chunk-fallback branch, and a reconciliation test.
</objective>
