## Phase Goal

**As a** reader who owns a long text, **I want to** upload it and have the app auto-detect its cast of characters and split it into voice-tagged narration/dialogue segments that I can review, correct, and preview per character, **so that** I get a multi-character narration set up with minimal manual editing.

> Note: the ROADMAP `**Goal:**` line for Phase 2 is outcome-shaped but third-person; the user story above is a direct reformatting of that goal plus its five success criteria, not an invented scope. Surfaced here per MVP-mode rules.

This plan delivers the first vertical slice end-to-end: upload a .txt, a background task detects a cast + segments (mock backend), and the API serves them back with live SSE progress. It is fully exercisable via pytest/curl without a GPU, a browser, or a real Grok key.

<objective>
Introduce real SQLModel/SQLite persistence (D-01/D-02) and the mock-backed background analysis pipeline (D-03/D-04) so an uploaded .txt produces a persisted, retrievable cast + ordered segments (CAST-01 shape, CAST-03), streamed via SSE for review (WIZ-01).

Purpose: Establishes the persistence schema, the shared Pydantic contract, and the async-worker + SSE machinery every later Phase 2 slice builds on — proven first with a mock LLM so the whole flow works with no network/GPU/key.
Output: `db.py`, `models.py`, `schemas.py`, `analysis_client.py` (mock + gated real), `token_estimate.py`, `analysis_worker.py`, rewired `/projects` endpoints, and a failing-first end-to-end pytest.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/curl -> POST /projects | Untrusted uploaded file bytes cross into the backend |
| backend -> SQLite | Persisted analysis data (single-process writer) |
| backend -> xAI Grok (Plan 03) | Untrusted book text sent to an external LLM |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | POST /projects upload read | high | mitigate | Reuse `_read_upload_bounded(file, MAX_UPLOAD_BYTES)` — bound the upload before decode/persist (unchanged from Phase 1). |
| T-02-02 | Tampering | uuid-based project id / file paths | medium | mitigate | Project id is server-generated `uuid4().hex`; never derive filesystem paths from the client filename (Phase 1 pattern reused). |
| T-02-03 | Information Disclosure | SQLite threading under asyncio background task | medium | mitigate | `create_engine(..., connect_args={"check_same_thread": False})` + fresh per-operation Session (Pitfall 4) to avoid cross-thread connection reuse / silent corruption. |
| T-02-SC | Tampering | `uv add sqlmodel xai-sdk` | high | mitigate | Task 1 blocking-human legitimacy checkpoint against pypi.org before install; both are [SUS] only due to the download-count tooling gap. |
</threat_model>
