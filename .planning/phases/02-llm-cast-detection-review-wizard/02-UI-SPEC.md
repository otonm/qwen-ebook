# Phase 2 — UI Design Contract

> Visual and interaction contract for the LLM Cast Detection & Review Wizard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (CLI v4.13.0, `create`-style init) |
| Preset | Scaffolded via `npx shadcn@latest init --template vite --base radix --preset nova -y -n frontend -c frontend` (this CLI generation's preset names are style themes — `nova`/`vega`/`maia`/`lyra`/`mira`/`luma`/`sera`/`rhea` — not color names; there is no `--base-color` flag on this CLI version). `components.json`'s `tailwind.baseColor` was then hand-set to `zinc` and `src/index.css`'s CSS variables replaced with the canonical shadcn "zinc" theme (`ui.shadcn.com/r/colors/zinc.json`, `cssVarsV4`) to match the user's explicit zinc decision — the CLI's own default output was `neutral` (0-chroma gray), close but not the requested palette. |
| Component library | Radix UI primitives (`radix-ui` package + `class-variance-authority` + `tailwind-merge`), shadcn "radix" base |
| Icon library | `lucide-react` (already installed by the shadcn scaffold — project default, no override needed) |
| Font | Inter — `@fontsource-variable/inter`, self-hosted variable font, no Google Fonts network call. Swapped in for the scaffold's default Geist per user decision. Loaded via `@import "@fontsource-variable/inter"` in `src/index.css`, wired to `--font-sans` in the `@theme inline` block. |
| Dark mode | CSS variables for `.dark` are present (shadcn always scaffolds both) but **not wired** this phase — no theme toggle, no `dark` class ever applied. Light mode only, per explicit user decision. Do not add a theme switcher without a follow-up design decision. |

**Repo state after this research pass:** `frontend/` now contains a real Vite + React 19 + TypeScript scaffold (previously only `.gitkeep`) with shadcn initialized, one component installed (`src/components/ui/button.tsx`), zinc+indigo theme applied in `src/index.css`, and `components.json` configured. `npm run build` verified clean. The planner/executor should `npx shadcn add <component>` for anything beyond `button` (card, input, badge, dialog, avatar, table, etc. — see Component Inventory below) rather than re-running `init`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside buttons/badges |
| sm | 8px | Compact spacing within a character card (label-to-value) |
| md | 16px | Default spacing between form fields, card internal padding |
| lg | 24px | Spacing between character cards, section padding |
| xl | 32px | Gap between the cast list and the segment preview panel |
| 2xl | 48px | Page-header-to-content spacing |
| 3xl | 64px | Not used this phase (no full-page marketing-style sections) |

Exceptions: none. Icon-only buttons (play/pause preview, merge, edit) use shadcn's standard `size="icon"` (36px/40px square, both multiples of 4) — no mobile touch-target exception needed, this is a desktop-only Tailscale tool (no mobile app, per PROJECT.md Out of Scope).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.4 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 24px | 600 (semibold) | 1.2 |

Two weights only: 400 regular (body text, segment text, descriptions), 600 semibold (headings, labels/badges, character names, primary CTA text). No 500/700 anywhere.

- **Body (14/400/1.5):** segment text in the read-only preview table, character description text, voice-instructions field content.
- **Label (12/600/1.4):** "NARRATOR" badge, preset name chip, field labels ("Voice Instructions", "Preset"), SSE progress text ("Analyzing chunk 2 of 5").
- **Heading (18/600/1.2):** character name at the top of each card, "Segments" section header above the read-only table.
- **Display (24/600/1.2):** page title ("Review Cast" / project filename as the page heading).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` (zinc `background`, pure white) | Page background, main content surface |
| Secondary (30%) | `oklch(0.967 0.001 286.375)` (zinc `secondary`/`muted`) | Character cards, segment preview table row stripe, right-adjacent panel background |
| Accent (10%) | `oklch(51.1% 0.262 276.966)` (Tailwind `indigo-600`, mapped to shadcn's `--primary` token) | See reserved list below — the **only** place accent color appears |
| Destructive | `oklch(0.577 0.245 27.325)` (shadcn default destructive red, unchanged) | Destructive actions and error states only |

**Accent reserved for** (explicit list — nothing else uses indigo):
- Primary CTA button ("Upload & Analyze")
- Play/pause preview button while actively playing (active/pressed state)
- Selected/focused character card's border or ring
- "Voice assigned" checkmark/indicator badge on a character card
- Text links (if any — e.g. a "view full segment" link, not expected this phase)

Everything else — card backgrounds, borders, secondary buttons ("Cancel", "Edit"), badges other than the assigned-voice indicator — stays zinc-neutral (background/secondary/muted/border tokens above). Do not use indigo for hover states, disabled states, or decorative accents.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Upload & Analyze"** — the initial file-upload action that creates the project and kicks off background Grok analysis (ING-01/ING-02/CAST-01) |
| Empty state heading | **"No book uploaded yet"** (pre-upload landing screen) |
| Empty state body | **"Upload a .txt or .epub file to auto-detect its cast of characters and split it into narrated segments."** + the Upload & Analyze CTA |
| Loading/analyzing state (not a template row, but load-bearing for this phase) | Heading: **"Analyzing your book…"** — Body: **"Detecting characters and splitting text into segments. This can take a minute for longer books."** — driven by SSE progress events (chunk N of M when multi-chunk fallback triggers, D-06/D-07) |
| Error state | **"Couldn't analyze this file."** + `{reason}` (e.g. "This chapter's markup couldn't be parsed." for D-13's fail-fast EPUB rejection, or "The analysis service didn't respond — try again." for a Grok API failure) + **"Fix the file and upload again."** as the next step |
| Destructive confirmation — merge character | **"Merge into {target character name}?"** — body: **"This removes '{source character name}' from the cast and reassigns its segments to {target character name}. This can't be undone automatically."** — confirm button label: **"Merge"** (not "OK"/"Yes") — cancel button label: **"Cancel"** |

No other destructive actions exist in this phase's scope (rename/edit-description/voice-assignment are all non-destructive, freely re-editable inline — matches D-14's spreadsheet-editing philosophy: edits auto-save via PATCH on blur/change, no separate "Save" button per field).
