<objective>
Wire model choice into the main backend: add the per-project `Project.tts_model` column (default `"1.7b"`), thread the model id through `compute_cache_key` so cross-model cache hits are impossible (Pitfall 4 / Pattern 2), add the `tts_client.load_model` HTTP helper, and add the `POST /projects/{id}/model` orchestration handler that claims the single-flight lock, drives the tts_service swap, and on success invalidates the project's segments and character previews (D-05/D-06 + RESEARCH Pitfall 4). Failed loads leave everything untouched (D-02).

Purpose: This is the orchestration half — it makes model choice a durable, cache-correct, per-project fact and gives the UI (Plan 03) its endpoint and its `tts_model` payload field.
Output: The column, the cache-key signature change, the client helper, and the swap endpoint.
</objective>
