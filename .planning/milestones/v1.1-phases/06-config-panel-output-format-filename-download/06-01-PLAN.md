<objective>
Add the full server side of per-project output format, filename, and download to the existing generation pipeline: two new `Project` columns, a 3-way ffmpeg codec dispatch (FLAC/MP3/Opus), a config PATCH endpoint, and a `FileResponse`-based download route. Every change follows an in-repo precedent (Phase 5 `tts_model` column, `patch_character`, `get_segment_audio`).

Purpose: CFG-06/07/08 are entirely mechanical extensions of already-parametrized code — this plan wires format/filename into DB state and adds the download surface without inventing any new mechanism.
Output: Extended `models.py`/`db.py`/`audio_join.py`/`generation_worker.py`/`config.py`/`main.py` plus unit/integration tests proving codec correctness, sanitization, and the download contract.

Decisions covered (see 06-CONTEXT.md):
- D-01: per-generation format (FLAC/MP3/Opus) driven from the Config Panel, read live at join time.
- D-02: persisted `Project.output_format` column, MP3 default (Task 1).
- D-03: persisted `Project.output_filename`, extension auto-derived from format (Task 1 + download route).
- D-07: only the latest output persists on disk (delete-old-before-join in `_join_project`).
- D-08: correct Content-Type per format, extension matches (download route via `CODEC_TABLE`).
- D-09: codec-availability spike — resolved in 06-RESEARCH.md (flac/mp3/opus all verified present in the ffmpeg build); no runtime probe needed.
- D-10: assume all three codecs available, no runtime fallback — `CODEC_TABLE` has no catch-all else, unknown fmt raises.
- D-11: `join_wavs(fmt)` is the single integration point, same if-dispatch pattern extended to a 3-key table.
- D-12: column defaults (`output_format` mp3, `output_filename` None) set in Task 1.
- D-13: format/filename flow through the existing pipeline unchanged — no queue/worker restructuring.
- D-14: previews stay WAV — this plan touches only the final join path, never the per-segment preview code.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /projects/{id} | Untrusted `output_format` and `output_filename` strings cross into DB state and (indirectly) an ffmpeg argv and a file-serving filename |
| DB `output_path` → GET /projects/{id}/download | Server-owned path is resolved to a file served back to the client |
| joined output → ffmpeg subprocess | Format string selects codec args passed to a subprocess argv (never a shell) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | output_filename reaching a filesystem write path | high | mitigate | On-disk path stays the server-generated `uuid4().hex` name in `_join_project`; `output_filename` is used only as the `FileResponse` display filename (Pitfall 8 / prohibitions block) |
| T-06-03 | Information Disclosure | download route path resolution | high | mitigate | Path resolved solely via `session.get(Project, id).output_path`; no client-supplied path/filename ever reaches `FileResponse`'s path arg |
| T-06-02 | Tampering | Content-Disposition header | medium | mitigate | `FileResponse(..., filename=)` builds the RFC-6266 header — no hand-formatted f-string (Pitfall 9); filename pre-sanitized of control/CRLF chars |
| T-06-04 | Tampering / DoS | output_format reaching ffmpeg argv | medium | mitigate | Validated against `CODEC_TABLE` keys at the PATCH boundary (422) and again by `join_wavs`' membership raise; subprocess called with an explicit arg list, never a shell |
| T-06-SC | Tampering | pip/npm installs | low | accept | No new packages installed this phase (RESEARCH Package Legitimacy Audit: N/A) — no supply-chain surface added |
</threat_model>
